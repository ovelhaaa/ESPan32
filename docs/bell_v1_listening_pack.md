# Bell V1 listening pack (M6.4)

Physical / critical listening is the primary gate for Bell V1. This pack is
deterministic and is regenerated on every host test run by
`tests/test_dsp.cpp::testBellM64ListeningPack`. The generated manifest with
per-file metrics and reference hashes is `bell_m64_listening_pack.md` (written
to the build directory and published as a CI artifact).

No DSP parameter is changed by generating this pack.

---

## 1. Candidates

| ID | Definition | Origin |
|---|---|---|
| **A** | `kPresetBell` current production baseline | compiled |
| **B** | A with tierce gain 0.65 -> 0.58 | host-only |
| **C** | B with hum 0.28 -> 0.24 and nominal 0.85 -> 0.90 | host-only |

A is the default and wins an unresolved tie (M6.2.1 rule). B and C are the
previously qualified focused candidate rounds. M6.4 adds no new candidate
matrix; these three are the maximum permitted rounds.

## 2. Files

Naming: `bell_m64_<section>_<detail>.wav`, 48 kHz stereo 16-bit PCM.

| Section | Coverage |
|---|---|
| `note_<midi>_v90` | register sweep 36/48/55/60/67/72/84, 4 s |
| `single_<midi>_v<vel>` | 48/60/72 x 30/60/90/110/127, 3 s |
| `interval_*` | D3+A3, D4+A4, C4+G4, 4 s |
| `chord4_v*` | four-note chord at 60/90/127, 4 s |
| `poly8_v*` | eight-note polyphony at 90/110, 4 s |
| `restrike_*` | soft->hard, hard->soft, +100 ms, +250 ms, 4 s |
| `roll` | 12 hits at 100 ms, 4 s |
| `abc_<fixture>_<A/B/C>` | raw timbre comparison, 4 s |
| `abc_<fixture>_<A/B/C>_matched` | same, RMS-matched to A |

The `_matched` files remove loudness as a decision cue without touching the
production limiter; they are generated by a host-side gain scale only.

## 3. Procedure

1. Listen in the intended order of play: `single_*`, `interval_*`, `chord4_*`,
   `poly8_*`, `restrike_*`, `roll`, then `note_*` for register consistency.
2. For each A/B/C fixture, prefer the `_matched` files so the louder candidate
   is not automatically preferred. Compare raw only to check that level
   matching did not hide a real character difference.
3. Score each dimension independently (no single "sounds good" score):
   pitch clarity, metallic identity, low-frequency hum balance, prime
   definition, tierce/quint audibility, high-mode harshness, doublet beating,
   attack realism, decay realism, velocity progression, register consistency,
   polyphonic density, restrike behaviour, tail smoothness, limiter
   interaction.
4. During the same session, also play fully live on hardware (soft/hard
   singles, 4-note chord, 8-voice passage, restrikes, roll, PAN/BELL switch)
   and record any audible click, dropout or instability. Any such defect stops
   the freeze; report `BELL V1 BLOCKED — audible realtime defect`.

## 4. Decision rule

- If no candidate clearly improves the musical result, **keep baseline A**.
- Do not change parameters merely to justify the milestone.
- Bell V1 is frozen only after a human listening decision is recorded here or
  in `bell_v1_freeze.md`.

## 5. Objective safety guards (already enforced by the host test)

For every generated fixture the host test asserts:

```text
hard clamp = 0
NaN / Inf = 0
max active voices <= 8
```

Modal safety-saturation counts are recorded, not forced to zero, because
saturation is intended behavior on extreme high-energy strikes. The measured
counts for the M6.4 pack were 0 across all baseline fixtures; the four-note
chord and eight-note polyphony reached pre-limiter peaks up to ~4.7 with the
limiter providing up to ~13.9 dB of gain reduction and no hard clamp.

## 6. Known constraint

The M6.4 pack is host-rendered. It validates timbre, balance and safety, not
real-time transport. The real-time behavior is covered by the frozen
[performance contract](performance_contract_v1.md).
